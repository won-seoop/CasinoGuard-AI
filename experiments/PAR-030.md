# PAR-030 Person Re-ID FC-014(Occlusion 저하) - Segmentation Mask 기반 Gray World로 완화

관련 실험: EXP-038 (Gamma-Background+White Balance 결합, FC-014 발견), EXP-039
(Segmentation Mask 기반 Gray World White Balance 검증)

## 1. 한줄 요약
White Balance의 Gray World 평균을 crop 전체가 아니라 Segmentation Mask로 추린 person
픽셀만으로 계산하도록 바꿔, EXP-038이 만든 FC-014(Occlusion Top-1 저하)를 세 방법
모두에서 역전 없이 완화(+4.44~+11.11pp)했다 - Roadmap이 직접 걸어둔 "Mask가 Occlusion
패치까지 포함해 효과가 없을 것"이라는 의심을, 패치-Mask 겹침을 코드로 직접 측정해
반증했다.

## 2. 문제가 뭐였는가?
EXP-038에서 Re-ID 임베딩의 조명 Cast(warm_cast/cool_cast) 붕괴를 Gamma-Background+White
Balance로 해결했지만, 그 부작용으로 Occlusion Top-1이 Baseline(Color Histogram)
-17.78pp, Candidate(YOLO Backbone) -4.44pp, Fusion -13.33pp로 세 방법 모두 일관되게
악화됐다(FC-014). White Balance의 Gray World 가정("crop 전체 채널 평균이 중립 회색에
가까워야 한다")이 중립 회색(120,120,120) Occlusion 패치 자체에 오염되는 것이 EXP-038이
이미 코드 레벨로 확인한 원인이었다.

## 3. 왜 이 문제가 중요했는가?
카지노 CCTV에서 사람 간 교차/가림(Occlusion)은 Tracking·Re-ID가 일상적으로 마주치는
가장 흔한 시나리오다(혼잡한 게이밍 플로어, 테이블 주변에 밀집한 사람들). 조명 Cast
문제를 고치려다 Occlusion 강건성을 희생하는 것은 이 프로젝트가 원래 더 중요하게
다루는 문제(카지노 환경에서 사람이 많고 교차가 빈번함, CLAUDE.md 지침 4)를 거꾸로
악화시키는 Trade-off였다. 연쇄 영향: Re-ID의 Occlusion 저하 → 가려졌다가 재등장하는
동일 인물을 다른 사람으로 오인 → 동선 분석/VMS 검색 정확도 저하 → Multi-Camera
환경에서의 추적 연속성 상실. 이 문제를 그대로 두면 FC-013(b)를 해결한 보정 자체를
production에 올릴 수 없다(EXP-038이 이미 그렇게 결론 내림).

## 4. 원인이 뭐였는가?
EXP-038이 이미 코드 레벨로 확인한 원인(중립 회색 Occlusion 패치가 crop 전체 평균을
오염시킴)을 그대로 인용했고, 이번 실험은 "그 원인을 어떻게 없애는가"를 검증했다.
핵심 측정: Occlusion 패치의 정확한 좌표를 RNG 소비 순서를 그대로 재현해 복원하고,
Segmentation Mask와의 겹침을 직접 계산했다(n=45, coco128 실제 crop) - 패치 영역이
`mask==True`에 포함되는 비율은 평균 15.87%, 패치 밖(옷이 보이는) 영역은 37.81%로,
22.0pp 차이가 있었다. 즉 Segmentation 모델이 중립 회색 평면 영역을 "사람"으로 보지
않고 Mask에서 상당 부분 제외하고 있었다 - Roadmap이 적어둔 "Mask가 패치까지 포함할
것"이라는 가정은 추측이었고, 실측으로 반증됐다.

## 5. A를 고민하였는데 왜 안 했는가?
**대안 A: Occlusion 패치를 명시적으로 탐지해 WB 평균 계산에서 제외(예: 중립 회색에
가까운 채도 낮은 영역을 Heuristic으로 찾아 제외)**. 장점은 Segmentation 모델 추론
비용(EXP-028 실측: Detector 단독 대비 1.29x)을 추가하지 않아도 된다는 것이다. 다만
이미 이 프로젝트가 "무채색 확신도" 신호(채도, raw BGR 표준편차)를 FC-012 맥락에서
검토했을 때 achromatic/chromatic 영역이 분리되지 않음을 실측으로 확인한 전례가
있다(EXP-027/PAR-018) - 진짜 무채색 옷(검정/회색/흰색)과 중립 회색 Occlusion 패치를
채도만으로 구분할 수 없어 같은 함정에 빠질 가능성이 높았다. 이미 반증된 접근을
다른 Task에 재시도하는 비용(개발 비용) 대비, 이 프로젝트가 이미 갖고 있는
Segmentation Mask(EXP-028/029에서 Attribute 분류에 검증·production 연결까지 완료된
재사용 가능한 구성요소)를 그대로 쓰는 것이 더 낮은 구현 복잡도와 더 높은 신뢰도를
가진다고 판단해 대안 A는 코드를 작성하지 않고 기각했다.

## 6. B를 고민하였고 왜 적용했는가?
**대안 B(채택): Segmentation Mask로 Gray World 평균 계산 범위를 person 픽셀에만
한정**. Roadmap(EXP-038 Next Action)이 이미 제안했고, 이 프로젝트가 Attribute 분류
(EXP-028/029)에서 이미 검증한 `segment_largest_instance_mask()`를 그대로 재사용할 수
있어 구현 복잡도가 낮았다. 가장 중요한 이유는 "가정하지 말고 실측한다"는 프로젝트
원칙에 따라, Roadmap 자신이 적어둔 반대 의심(Mask가 패치를 포함해 효과 없을 것)을
먼저 실측으로 확인/반증할 수 있는 방법이기도 했다는 점이다 - 대안 A는 애초에
"무채색 신호 분리 불가"라는 이미 검증된 실패를 반복할 뿐이라 비교 대상으로서의
가치도 낮았다.

## 7. 어떤 방식으로 검증했는가?
- Dataset: coco128 실제 person crop 45명(Gallery, `results/EXP-027/crops`,
  EXP-027/036/037/038과 완전히 동일한 집합 - 실행 시 재탐지로 검증).
- Query: EXP-036/037/038과 완전히 동일한 Protocol(RNG seed 42, 동일 호출 순서) - 조명
  4종 + 기하 변형 3종(occlusion/bbox_jitter/flip) = 315 Query.
- Configuration: `white_balance_gray_world_masked()`/
  `gamma_background_then_white_balance_masked()`(신규, `src/attributes/color.py`) -
  mask 유효 픽셀 5% 미만이면 전체 픽셀 기준으로 폴백. Mask는 `segment_largest_instance_mask`
  (yolo11n-seg.pt)로 변형이 이미 적용된 이미지 자체에서 직접 추론(실제 운영 조건과
  동일).
- Baseline: EXP-038의 Masking 없는 `gamma_background_then_white_balance`를 이 실험에서
  재실행해 재현성 확인(Overall/Variant별 수치가 EXP-038 기록과 완전히 일치).
- Metric: Top-1(Overall + Variant별), mAP, Baseline(Color Histogram)/Candidate(YOLO
  Backbone)/Fusion(50:50) 세 방법 모두 측정.
- 비교 방식: 같은 Gallery/Query/RNG Seed로 Masking 유무만 바꿔 Before/After 비교.
- Regression Test: `pytest tests/ -q` 전체 재실행(304 passed/7 skipped - 기존 298에서
  신규 6개만 추가, 회귀 없음). 신규 결정론적 합성 픽셀 Unit Test 6개
  (`TestWhiteBalanceGrayWorldMasked` 4개, `TestGammaBackgroundThenWhiteBalanceMasked`
  2개)가 "Occlusion 패치가 Mask 밖이면 평균에 영향을 주지 않는다"는 핵심 메커니즘
  자체를 고정한다.

## 8. 개선된 수치적인 결과가 무엇이었는가?

| Metric | Before (Masking 없음, EXP-038) | After (Mask 기반, EXP-039) |
|---|---|---|
| Baseline Occlusion Top-1 | 0.6222 | **0.7333 (+11.11pp)** |
| Candidate Occlusion Top-1 | 0.7333 | **0.7778 (+4.44pp)** |
| Fusion Occlusion Top-1 | 0.7556 | **0.8000 (+4.44pp)** |
| Baseline Overall Top-1 | 0.6857 | 0.7079 (+2.22pp) |
| Candidate Overall Top-1 | 0.7492 | 0.7492 (0) |
| Fusion Overall Top-1 | 0.7778 | 0.8000 (+2.22pp) |
| Fusion warm_cast Top-1 | 0.9556 | 0.9333→1.0000 (+4.44pp, Regression 없음) |
| Fusion cool_cast Top-1 | 0.8889 | 0.9333 (+4.44pp, Regression 없음) |
| 패치 영역의 Mask 포함률 (진단) | - | 15.87% |
| 패치 밖 영역의 Mask 포함률 (진단) | - | 37.81% (차이 22.0pp) |

Candidate low_light/bbox_jitter 각 -2.22pp(모두 45 Query 중 1건 수준의 변동).

## 9. 재발 방지 대책
- 신규 함수(`white_balance_gray_world_masked`, `gamma_background_then_white_balance_masked`)
  에 결정론적 합성 픽셀 Unit Test 6개를 추가해 "Mask 밖 픽셀은 평균에 영향을 주지
  않는다"는 핵심 메커니즘과 "Mask 유효 픽셀 5% 미만이면 전체 픽셀로 폴백한다"는
  경계 조건을 Regression Test로 고정했다(`tests/test_attribute_color.py`).
- "Roadmap에 적힌 가정(Mask가 패치를 포함할 것)이라도 검증 없이 production 설계에
  반영하지 않는다"는 이 프로젝트의 원칙을 다시 지켰다 - 패치-Mask 겹침을 RNG 재현으로
  정밀 측정하는 보조 진단을 코드로 남겨(세션 스크래치, 재현 가능한 로직은 experiment.md
  Result에 명시) 추측이 아니라 실측 근거로 결론을 냈다.
- Masking 기반 WB는 여전히 production(`src/reid/`, `run_full_pipeline.py`)에 연결하지
  않았다 - n=45 합성 Query 한계와 Segmentation 추론 비용(미실측)이 해소되기 전까지
  이 경계를 지킨다. 다음 세션이 실수로 바로 연결하지 않도록 EXP-039 experiment.md
  Decision에 이유를 명시했다.
- 다음 후보(low_light/strong_light 추가 악화 원인의 Gray World 게인 직접 로깅, n 확장,
  실제 CCTV 영상에서의 재검증)는 EXP-039 Next Action에 구체적으로 남겼다.
