# PAR-027 Person Re-ID Baseline 구축 - 평균 지표로는 보이지 않는 두 임베딩의 상호 배타적 강점, 그리고 Score Fusion이 오히려 손해를 보는 메커니즘

관련 실험: EXP-027(PAR-018, coco128 person crop 확보), EXP-035(PAR-026, Next
Action에서 Person Re-ID를 다음 Stretch 후보로 지정), EXP-036

## 1. 한줄 요약
지침 18 Person Re-ID의 첫 Baseline을 구축하면서 Color Histogram과 YOLO Backbone
임베딩을 비교한 결과, 전체 평균(Top-1)으로는 YOLO Backbone이 더 낫다는 결론이
나오지만 조건별로 분해하면 두 방법은 완전히 다른(공간 변형 vs 조명 Cast) 조건에서
이기고 지는 상호 배타적 강점을 가진다는 것을 발견했고, "그러면 둘을 합치면 더
좋아지지 않을까"라는 자연스러운 다음 가설(50:50 Score Fusion)도 실측으로
반증했다 - 한쪽이 "확신 있게 틀리는" 조건에서는 평균이 다른 쪽의 거의 완벽한
신호까지 끌어내린다.

## 2. 문제가 뭐였는가?
Core MVP와 Attribute Metadata(FC-012 계열)에 집중하는 동안 Person Re-ID(지침 18)
는 전혀 손대지 않은 채 Roadmap에 "[ ] (Stretch) Person Re-ID 미착수"로 남아
있었다. 이 기능을 처음 구현하면서, "Deep Pretrained 임베딩이 고전적 Color
Histogram보다 더 나을 것"이라는 가장 직관적인 가설을 그냥 믿고 승격하는 대신
실제로 측정했을 때 그 결론이 조건에 따라 완전히 달라진다는 것을 발견했다.

## 3. 왜 이 문제가 중요했는가?
Person Re-ID는 Multi Camera 환경(카지노의 여러 CCTV)에서 "이 사람이 다른
카메라에서도 같은 사람인가"를 판단하는 핵심 기능이다(지침 18). 카지노 환경은
조명이 구역마다 크게 다르고(테이블 위 강한 인공조명, 복도의 차갑거나 따뜻한
조명), 사람이 겹치고 가려지는 상황(Occlusion)이 흔하다 - 이번 실험이 측정한
Variant(조명 Cast/저노출·과다노출/Occlusion/Bbox Jitter)가 정확히 카지노 CCTV가
일상적으로 겪는 조건들이다. 만약 "평균 지표가 더 좋다"는 이유만으로 Deep
임베딩을 그대로 production에 썼다면, Baseline이 거의 완벽했던 Occlusion
상황(바로 카지노의 핵심 문제)에서 오히려 Top-1이 20pp 하락하는 Regression을
알아차리지 못했을 것이다. 또한 "두 신호를 합치면 더 안전할 것"이라는 Fusion에
대한 암묵적 직관도 이번에 반증됐는데, 이는 향후 다른 기능(예: Attribute+Re-ID
결합 검색)에서도 "합치면 무조건 낫다"고 가정하지 않아야 한다는 경고로
연쇄적으로 작용한다.

## 4. 원인이 뭐였는가?
`results/EXP-036/summary.json`의 Variant별 분해(experiment.md Result 2/3 표
참고)를 직접 근거로 확인했다:
- Baseline(Color Histogram)은 Flip 100%/Bbox Jitter 95.6%/Occlusion 84.4%로
  공간 변형에 거의 완벽하다 - Histogram은 위치 정보를 버린 전역 통계이므로
  구조적으로 평행이동/대칭에 불변하다는 것이 코드(`color_histogram_embedding`)
  로도 확인 가능한 사실이다.
- 대안 B(YOLO11n-cls Backbone)는 warm_cast/cool_cast에서 100%를 내지만
  Bbox Jitter 66.7%/Occlusion 64.4%로 공간 변형에는 Baseline보다 약하다 -
  ImageNet 분류기가 전체 이미지 Context(객체가 Frame 중앙에 일정 비율로 놓여
  있다는 가정)에 의존하도록 학습됐기 때문으로 보인다.
- Fusion(50:50)이 warm_cast/cool_cast에서 100%→26.7%/20.0%로 무너진 원인은
  `per_query_predictions.csv`로 직접 확인했다: 이 Variant에서 Baseline은 오답
  Gallery 인물에 상대적으로 높은 Cosine Similarity를 주고 있었다(단순히 낮은
  신뢰도가 아니라 "확신 있는 오답") - 가중 평균은 대안 B의 거의 완벽한 정답
  신호를 이 확신 있는 오답 신호로 깎아내린다. 공간 변형 Variant에서는 두 방법의
  오답 방향이 겹치지 않거나 약해서(Occlusion은 오히려 Fusion이 둘 다를
  능가 - 88.9%) 평균이 손해를 보지 않았다.

## 5. A를 고민하였는데 왜 안 했는가?
대안 A: OSNet(torchreid 생태계의 Person Re-ID 전용 Pretrained 모델). 장점: 사람
전용으로 학습되어 Baseline/YOLO Backbone보다 훨씬 높은 판별력을 가질 것으로
기대된다. 실제로 구현을 시작하기 전에 Weight 호스팅 위치를 `curl`로 직접
확인했는데, `drive.google.com`이 403(CONNECT tunnel failed)으로 막혀 있었고
해당 모델의 GitHub 저장소 페이지(`github.com/KaiyangZhou/deep-person-reid`,
Release Asset이 아닌 일반 페이지)도 403이었다 - 이 세션의 egress 정책이 pypi와
GitHub Release Asset만 허용하고 Google Drive는 차단한다는 것을 추측이 아니라
실측으로 확인했으므로, 코드를 작성하기 전에 기각했다(이전 EXP-027/028/035
세션들이 이미 확인한 "GitHub Release Asset은 되고 그 외 호스팅은 막힌다"는
패턴과 일치).

## 6. B를 고민하였고 왜 적용했는가?
대안 B: yolo11n-cls.pt(ImageNet Pretrained 분류 Backbone)의 최종 분류 Layer
직전 GAP 특징을 범용 임베딩으로 재사용. A와 달리 Weight가 GitHub Release
Asset으로 바로 접근 가능했고(실측 200 확인), 이미 이 프로젝트의 Detection/
Segmentation이 쓰는 것과 동일한 YOLO 계열 모델 파일 포맷이라 Edge Camera에
새로운 모델 Runtime을 추가하지 않아도 된다는 배포 비용 장점이 있었다(지침 25
Edge Device SW 연결). Person Re-ID 전용이 아니라는 명백한 한계가 있지만, 그
한계를 포함해 실제로 측정하는 것이 이번 실험의 목적이었다.

## 7. 어떤 방식으로 검증했는가?
Dataset: coco128 실제 person crop 45장(`results/EXP-027/crops/*.jpg`, 32개
COCO 이미지에서 추출된 45명의 서로 다른 실제 인물)을 Gallery로, 각 인물마다
7종 합성 Query 변형(조명 4종[EXP-025/027과 동일 공식]+Occlusion+Bbox Jitter+
수평 Flip)을 만들어 315개 Query로 평가했다. Configuration: Baseline(Color
Histogram, HSV 8x8x8 bin)과 대안 B(YOLO11n-cls GAP 특징)를 각각, 그리고 둘의
Cosine Similarity를 50:50으로 가중 평균한 Fusion을 비교했다. Metric: Top-1,
Top-5, mAP(지침 18 권장 Metric)를 전체 315개와 Variant별 45개 단위로 각각
집계(`evaluate_identification()`, `rank_gallery_fused()`). Regression Test:
`tests/test_reid_matching.py` 신규 21개 - Cosine Similarity 경계값(동일/직교/
반대/영벡터), 랭킹 정렬 정확성, Top-K/AP 공식의 알려진 입력에 대한 정확한
수치, Fusion 가중치 정규화와 오류 처리까지 결정론적으로 고정했다(외부 모델
의존 없이 numpy만으로 테스트). `pytest tests/ -q` 전체 295 passed/7
skipped(기존 274에서 신규 21개만 추가, 회귀 없음).

## 8. 개선된 수치적인 결과가 무엇이었는가?

| Metric | Baseline(Color Histogram) | 대안 B(YOLO Backbone) | Fusion(50:50) |
|---|---|---|---|
| 전체 Top-1 | 49.21% | **59.68%** | 52.38% |
| 전체 Top-5 | 67.62% | **71.75%** | 70.16% |
| 전체 mAP | 0.5809 | **0.6614** | 0.6163 |
| warm_cast Top-1 | 17.78% | **100.0%** | 26.67% |
| cool_cast Top-1 | 11.11% | **100.0%** | 20.00% |
| flip Top-1 | **100.0%** | 84.44% | 100.0% |
| bbox_jitter Top-1 | **95.56%** | 66.67% | 95.56% |
| occlusion Top-1 | 84.44% | 64.44% | **88.89%**(Fusion이 둘 다 능가) |
| low_light Top-1 | **33.33%** | 2.22% | 22.22% |
| strong_light Top-1 | 2.22% | 0.00% | 13.33% |

전체 평균 기준으로는 대안 B가 Baseline을 앞서지만(가설 1 확인), Fusion은 대안 B
단독보다 전체 Top-1이 7.3pp 낮다(가설 2 반증) - Variant별 분해가 평균만 봐서는
알 수 없는 Trade-off(그리고 Fusion의 역효과 메커니즘)를 드러냈다.

## 9. 재발 방지 대책
1. **Regression Test**: `tests/test_reid_matching.py`(21개)가 Cosine Similarity/
   랭킹/Top-K/AP/Fusion 공식 자체를 외부 모델 의존 없이 고정해, 향후 임베딩
   방식이 바뀌어도(예: 대안 B를 다른 Backbone으로 교체) 평가 로직 자체의 정확성은
   항상 재검증된다.
2. **Failure Case 등록**: FC-013(저노출/과다노출에서 두 방법 모두 Re-ID 붕괴)을
   `experiments/EXP-036/experiment.md`의 Failure Cases에 명시적으로 남겨, 다음
   세션이 "Re-ID를 그냥 production에 연결"하기 전에 이 조건을 먼저 확인하도록
   했다.
3. **방법론 원칙(재사용 가능)**: "평균 지표가 더 좋다"는 결론은 항상 Condition/
   Variant 단위로 재분해해 역전되는 하위집합이 있는지 확인해야 한다는 이
   프로젝트의 반복된 교훈(PAR-017/023/026)이 Re-ID에도 동일하게 적용됨을
   확인했다. 추가로 "두 신호를 합치면 더 안전하다"는 가정도 그 자체로 검증
   대상이며, 한쪽이 특정 조건에서 확신 있게 틀리는 경우에는 반대로 작동할 수
   있다는 새로운 경계심을 다음 Fusion 설계(Attribute+Re-ID 결합 검색 등)에
   남긴다.
4. **Dataset 한계 명시**: 이번 평가는 Query가 실제 재촬영이 아니라 합성 변형이라는
   한계가 있다(experiment.md Dataset 참고). production 승격 기준에는 이 한계를
   계속 포함시켜, 합성 Query에서의 우위만으로 production에 올리지 않는다는 결정을
   `evaluation/`이 아닌 `experiments/EXP-036/experiment.md` Decision에 명시적으로
   남겼다.
