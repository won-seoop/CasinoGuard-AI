# PAR-028 Person Re-ID 저노출/과다노출 붕괴(FC-013)를 배경 기반 Gamma 보정으로 부분 완화

관련 실험: EXP-036(PAR-027, FC-013 최초 발견), EXP-030(PAR-021, 같은 보정을 Attribute
분류에서 먼저 검증한 선행 실험), EXP-037(이번 실험)

## 1. 한줄 요약

Person Re-ID 임베딩(Color Histogram/YOLO Backbone)이 저노출/과다노출에서 거의
무작위로 붕괴하던 FC-013을, 같은 Frame의 배경에서 추정한 Gamma 보정을 임베딩 추출
전에 적용해 strong_light Top-1을 0.0%→66.7%(YOLO Backbone)까지 개선했고, crop 자신의
밝기로 추정하는 대안보다 Occlusion 등 다른 조건을 덜 희생시킨다는 것을 실측으로
확인했다.

## 2. 문제가 뭐였는가?

EXP-036에서 Person Re-ID Baseline(Color Histogram)과 대안 B(YOLO11n-cls Backbone
임베딩) 둘 다 합성 저노출(low_light, `img*0.35`)/과다노출(strong_light, `img*1.9+25`)
Query에서 Top-1이 거의 무작위 수준으로 붕괴했다(Baseline low_light 33.3%/strong_light
2.2%, 대안 B low_light 2.2%/strong_light 0.0% - 45명 중 단 한 명도 자신을 1위로 찾지
못함). 50:50 Score Fusion으로도 구제되지 않아 FC-013으로 등록만 하고 백로그에 남아
있었다.

## 3. 왜 이 문제가 중요했는가?

카지노 CCTV는 슬롯머신 조명, 역광이 심한 출입구, 야간 저조도 복도 등 조명 조건이
극단적으로 변하는 환경을 수백~수천 채널로 운영한다(CLAUDE.md 지침 8). Person Re-ID는
Multi-Camera 환경에서 "같은 사람이 다른 카메라/다른 시간대에 다시 나타났는가"를
판별하는 기능인데, 바로 그 "다른 카메라"가 종종 다른 조명 조건을 의미한다 - 입구(강한
인공조명)에서 본 사람이 어두운 복도 카메라에 다시 나타나면 임베딩이 붕괴해 못 찾는
것은 기능 자체의 핵심 전제를 깨뜨린다. 연쇄 영향: Re-ID 실패 → 동일인 재식별 불가 →
Multi-Camera 동선 추적 불가 → 수사/포렌식 검색("이 사람이 또 어디서 나타났는가")에서
결정적 단서를 놓침. FC-012(Attribute 색상 분류)가 이미 겪은 "노출 극단값에서 색 기반
신호가 무너진다"는 문제가 Re-ID라는 다른 기능에서도 같은 근본 원인(전역 노출)으로
재현된다는 것을 확인한 것도 중요하다 - 이 프로젝트의 여러 Visual Perception 기능이
독립적이지 않고 같은 카메라 노출 문제에 공통으로 취약하다는 구조적 통찰이다.

## 4. 원인이 뭐였는가?

EXP-036의 `results/EXP-036/summary.json`(`baseline_by_variant`/`candidate_by_variant`)
에서 low_light/strong_light Top-1이 다른 Variant(flip 100%, warm_cast 100% 등)에 비해
압도적으로 낮음을 직접 확인했다. EXP-037에서 배경 기반 Gamma 보정(같은 Frame의 person
bbox 밖 영역 평균 밝기로 노출을 추정해 역보정)을 적용하자 정확히 이 두 조건만
표적대로 크게 개선됐다(strong_light 대안 B 0.0%→66.7%, Baseline 2.2%→28.9%) - 반면
Gamma 보정이 겨냥하지 않는 원인을 가진 조건(warm_cast/cool_cast, 채널 간 상대적
Cast)은 개선되지 않고 오히려 소폭 악화됐다. 이는 "전역 노출 변화가 원인"이라는
가설을 로그/Metric으로 직접 뒷받침한다(추측이 아니라 EXP-037 summary.json의
variant별 수치로 확인).

## 5. A를 고민하였는데 왜 안 했는가?

대안 A(Gamma-Self): crop 자신의 평균 밝기로 감마를 추정해 자신에게 적용
(`adaptive_gamma_correct`, 배경 불필요, 더 단순). EXP-037에서 실제로 구현·측정한
결과 전체 집계 지표(Baseline/대안B/Fusion Top-1·mAP)에서 대안 B보다 낮거나 같았고
(예: Fusion Top-1 62.54% < 63.49%), 특히 카지노 핵심 실패 모드인 Occlusion에서 대안
B보다 훨씬 크게 희생시켰다(Baseline Occlusion 84.4%→68.9%, -15.6pp vs 대안 B의
84.4%→80.0%, -4.4pp). 대안 A가 유일하게 더 나았던 지점(대안 B 임베딩의 low_light
46.7% vs 33.3%)만으로는 이 Trade-off를 정당화하기에 부족하다고 판단했다 - 이
프로젝트가 PAR-018/023/026에서 반복 확인한 "한 지표의 개선만 보고 결정하지 않는다"
원칙을 그대로 적용했다.

## 6. B를 고민하였고 왜 적용했는가?

대안 B(Gamma-Background): 같은 Frame의 배경(person bbox 밖)에서 노출을 추정해 crop에
적용. EXP-030(Attribute 분류)이 이미 "crop 자신의 밝기는 옷 색상(albedo)과 노출이
혼합된 신호라 confound가 생긴다"는 이유로 대안 A를 기각하고 이 방식을 채택한 선례가
있었는데, EXP-037에서 Re-ID에 그대로 적용해 측정한 결과 대안 A보다 모든 헤드라인
집계 지표에서 역전 없이 같거나 나았고(동률 포함), 특히 Occlusion/Bbox Jitter 보존이
뚜렷하게 우수했다(대안 B 임베딩 Bbox Jitter 66.7%→62.2%, -4.4pp vs 대안 A의
66.7%→57.8%, -8.9pp). 노출(Gamma 영역)과 Cast(White Balance 영역)가 서로 다른
원인이라는 FC-012의 기존 분해를 그대로 재사용할 수 있어, 다음 단계(Cast까지 해결)로
자연스럽게 이어지는 설계이기도 했다.

## 7. 어떤 방식으로 검증했는가?

Dataset: EXP-027/036과 완전히 동일한 coco128 실제 person crop 45명(Gallery) + 같은
RNG 시드(42)로 만든 315개 합성 Query(low_light/strong_light/warm_cast/cool_cast/
occlusion/bbox_jitter/flip, 7종 x 45명). 배경 추출을 위해 coco128을 EXP-030과 동일
설정(yolo11n.pt, conf=0.4, `MIN_BOX_AREA=120*250`)으로 재탐지했고, 재탐지 결과가
EXP-027/036 Gallery 45명과 정확히 일치함을 코드 내 `RuntimeError` 가드로 실행 시점에
직접 검증했다(실제로 불일치 0건). Baseline(No-Gamma)이 EXP-036과 완전히 동일한
수치(Top-1 49.21%/59.68%)로 재현됨을 먼저 확인해 측정 환경 자체의 신뢰성을
확보했다. Environment: opencv-python-headless 5.0.0, ultralytics(`yolo11n.pt`,
`yolo11n-cls.pt`), torch(CPU), 모두 GitHub Release Asset 경로로 이 세션에서 재다운로드
(egress 정책 내 접근 가능 확인). Configuration: No-Gamma(기준선) vs 대안 A(Gamma-Self)
vs 대안 B(Gamma-Background), 둘 다 Gallery+Query 양쪽에 동일 파이프라인 적용(조건을
사전에 알고 선택 적용하는 치팅 방지). Metric: Top-1/Top-5/mAP, 전체 집계 + Variant별
집계(7종) 모두 기록. Regression Test: `src/attributes/color.py`/`src/reid/` 기존 소스는
전혀 수정하지 않았고(실험은 스크립트 레벨에서만 기존 함수를 조합), 전체 `pytest
tests/ -q`가 실험 전후 동일하게 295 passed/7 skipped임을 확인해 회귀가 없음을
검증했다.

## 8. 개선된 수치적인 결과가 무엇이었는가?

| Metric | No-Gamma | Gamma-Self(A) | Gamma-Background(B, 채택) |
|---|---|---|---|
| Baseline(Color Histogram) strong_light Top-1 | 2.2% | 28.9% | 28.9% |
| 대안 B(YOLO Backbone) strong_light Top-1 | 0.0% | 60.0% | **66.7%** |
| 대안 B(YOLO Backbone) low_light Top-1 | 2.2% | **46.7%** | 33.3% |
| Baseline 전체 Top-1 / mAP | 49.21% / 0.5809 | 49.52% / 0.5972 | **51.11%** / **0.6020** |
| 대안 B 전체 Top-1 / mAP | 59.68% / 0.6614 | 73.97% / 0.7959 | **74.29%** / **0.8005** |
| Fusion(50:50) 전체 Top-1 / mAP | 52.38% / 0.6163 | 62.54% / 0.7125 | **63.49%** / **0.7193** |
| Baseline Occlusion Top-1(부작용 측정) | 84.4% | 68.9%(-15.6pp) | 80.0%(-4.4pp) |

대안 A가 대안 B 임베딩의 low_light에서 유일하게 더 나았지만(46.7% vs 33.3%), 세
가지 헤드라인 집계 지표 전부와 Occlusion 보존 모두에서 대안 B가 역전 없이 지배했다
(선택 근거, 5/6번 참고). warm_cast/cool_cast(채널 Cast)는 두 대안 모두 개선하지
못했고 오히려 2.2~8.9pp 소폭 악화됐다 - Gamma 보정이 겨냥하지 않는 원인이므로 예상된
결과이며, 숨기지 않고 그대로 기록했다.

## 9. 재발 방지 대책

- `experiments/EXP-037/experiment.md`에 대안 A/B 전체 Variant별 수치(개선·부작용
  모두)를 투명하게 기록해, 다음 세션이 "대안 B가 만능"이라고 오해하지 않고
  warm_cast/cool_cast가 여전히 미해결임을 바로 알 수 있게 했다.
- Gamma-Background 보정은 아직 `src/reid/`의 재사용 가능한 함수로 승격하지 않고
  실험 스크립트(`scripts/run_exp037_reid_gamma_correction.py`)에만 존재한다 -
  production(`MetadataStore`/`run_full_pipeline.py`) 연결 전에 (1) White Balance
  결합이 warm_cast/cool_cast를 실제로 개선하는지, (2) 실제 Wide-angle CCTV 영상(합성
  Query가 아닌 진짜 재등장 Track)에서도 유지되는지를 먼저 검증해야 한다는 조건을
  Next Action에 명시해, 검증되지 않은 채 조용히 production에 들어가는 것을 막았다.
- Baseline(No-Gamma) 재현치(Top-1 49.21%/59.68%)를 experiment.md에 고정해 둬서,
  다음 세션이 이 실험을 이어갈 때 같은 재현성 확인을 반복할 수 있는 기준점으로
  삼게 했다.
- 기존 `pytest tests/ -q`(295 passed/7 skipped)를 실험 전후 재실행해 회귀가 없음을
  확인했다 - 이 실험은 src 코드를 바꾸지 않았으므로 새 Unit Test는 추가하지 않았다
  (EXP-030 등 선행 실험과 동일하게, 재사용 가능한 로직은 이미 `tests/
  test_attribute_color.py`/`tests/test_reid_matching.py`가 커버한다).
