# PAR-025 그림자 제거 필터 2차 Sweep - val_min은 끝까지 밀어도 되지만 sat_min은 아니다

관련 실험: EXP-033(PAR-024), EXP-034

## 1. 한줄 요약
EXP-033이 근사치로만 확인한 val_min=0(그림자 제거 필터 완전 제거)을 실제 Mask+WB
production 경로에서 직접 검증해 Overall Accuracy를 49.05%→50.48%(+1.4pp)로 더
끌어올렸지만, 같은 방식으로 sat_min(채도 하한)을 낮추는 두 번째 실험에서는 "낮출수록
좋아질 것"이라는 가설이 반증되어 비단조(U자형) 패턴을 발견했고, sat_min=20이라는
부작용 없는 값만 추가로 채택했다.

## 2. 문제가 뭐였는가?
EXP-033은 val_min을 35->10으로 낮추는 안을 채택하면서, "val_min을 더 낮출수록
계속 좋아진다"는 근거로 사후 Sweep을 하나 남겼다 - 그런데 그 Sweep은 production이
실제로 쓰는 `classify_person_attributes_with_mask_and_wb_relaxed`(Segmentation
Mask+White Balance 포함)가 아니라, 그 둘을 뺀 `region_dominant_color` 단독
(method "b") 근사치였다. 또한 `region_dominant_color`의 또 다른 필터 파라미터인
sat_min(채도 하한)은 어떤 실험에서도 기본값(25)에서 건드려 본 적이 없었다.

## 3. 왜 이 문제가 중요했는가?
"근사치로 확인한 추세를 실제 경로에서 재확인하지 않고 그대로 Production 결정에
쓰는 것"은 카지노 CCTV처럼 여러 필터·보정이 체인으로 연결된 실시간 시스템에서
특히 위험하다 - Segmentation Mask나 White Balance 같은 선행 단계가 필터
파라미터의 민감도 자체를 바꿀 수 있기 때문이다(실제로는 이번엔 바뀌지 않았지만,
확인 전에는 몰랐다). 더 중요하게, 이번 실험은 "한 Threshold 파라미터(val_min)에서
확인한 단조 추세를 유사한 역할의 다른 파라미터(sat_min)에도 그대로 가정하면
안 된다"는 일반 원칙을 실측으로 확인했다 - 다음에 Loitering Threshold나 BestShot
가중치처럼 여러 유사 역할의 Threshold를 함께 튜닝할 때도, 하나가 단조라고 해서
나머지도 단조라고 가정해서는 안 된다는 재사용 가능한 경계심이다. Attribute
Metadata는 아직 VMS Search API에 연결되지 않았지만(지침 19), 연결되는 순간
검색 정확도가 되므로 이 필터 체인의 동작을 정확히 이해해 두는 것이 선행 작업이다.

## 4. 원인이 뭐였는가?
`results/EXP-034/predictions.csv`에서 sat_min Sweep 6개 값 중 적어도 하나가 다른
값들과 판정이 다른 GT=black cell(210개 중 6개)을 직접 추적해 두 가지 메커니즘을
확인했다:
- 사례 1(`000000000536_0` upper): sat_min을 낮출수록 필터를 통과하는 저채도
  Noise가 늘어 Hue 다수결의 median이 점진적으로 오염되다가 어느 지점에서
  `classify_hsv_pixel` 자체의 S<30 "gray" 분기로 넘어간다(단조적 악화).
- 사례 2(`000000000634_0` lower): sat_min=25/20에서는 정답("black")이지만
  sat_min=15/10/5 "중간 지대"에서만 "gray"(오답)로 떨어지고, sat_min=0에서
  다시 "black"(정답)으로 복귀한다. 결정론적 합성 픽셀로 재현해 확인한 원인은
  "필터를 엄격하게 하면(sat_min=25) 중간 채도 오염이 필터에 걸려 제외되고
  min_filtered_fraction 폴백이 발동해 진짜 어두운 다수가 이기지만, 필터를
  '딱 중간만' 완화하면 오염은 필터를 통과하는데 진짜 어두운 다수(S가 더 낮음)는
  여전히 통과하지 못해 오염이 다수결을 가져가고, 필터를 완전히 버리면(sat_min=0)
  진짜 어두운 다수까지 전부 포함되어 수(count) 기준으로 다시 우세해진다"는
  것이었다 - 이것이 U자형 비단조 패턴의 정확한 메커니즘이다.

## 5. A를 고민하였는데 왜 안 했는가?
대안 A: "val_min=0과 sat_min=0을 모두 가장 낮은 값으로 설정한다"(두 Sweep 모두
끝까지 민다는 가장 단순한 확장). 장점: 구현이 가장 쉽고, Overall Accuracy도
50.95%로 sat_min=20과 동률이다. 하지만 GT=black Accuracy가 77%로 sat_min=20의
79%보다 2pp 낮고, 조건별로 보면 normal/strong_light는 개선되지만 warm_cast/
cool_cast의 GT=black 정확도가 0.9->0.85로 떨어지는 부작용이 측정됐다(원인 분석의
사례 2와 같은 메커니즘이 다른 cell에서는 여전히 작동). "낮출수록 좋다"는 가설이
이미 반증된 상태에서 가장 낮은 값을 그대로 쓰는 것은 근거 없는 선택이었다.

## 6. B를 고민하였고 왜 적용했는가?
대안 B(채택): val_min=0은 그대로 두고(실제로 유일하게 단조 개선이 확인된
파라미터), sat_min만 Sweep 결과에서 "Baseline(25)을 모든 측정 지표에서 역전 없이
순수하게 지배하는" 20으로 설정한다. Overall(+0.47pp)·GT=black(동일, 0 손실)·
비검정 GT(+0.9pp) 모두에서 Baseline보다 나쁘지 않거나 더 낫고, 조건별로도 역전이
전혀 없다(warm_cast만 개선, 나머지 4개 동일). sat_min=0보다 절대적으로 더 좋은
수치(Overall)는 아니지만, "부작용이 전혀 없다"는 조건을 만족하는 유일한 값이었고
이 프로젝트가 EXP-033에서 세운 원칙(겨냥한 개선이 다른 구간에 부작용을 주는지
항상 슬라이싱해서 확인)과 일치한다.

## 7. 어떤 방식으로 검증했는가?
Dataset: EXP-027/028/030/031/032/033과 완전히 동일한 coco128 n=21 person crop
Ground Truth(EXP-032/033의 GT 라벨 교정 2건 반영) + 동일 5종 합성 조명(normal/
low_light/strong_light/warm_cast/cool_cast). Configuration: `src/attributes/
color.py`의 `classify_person_attributes_with_mask_relaxed`에 `sat_min` 파라미터를
신규 노출(기본값 25로 EXP-033 당시 동작과 완전히 동일 유지, 기존 공개 함수는
전혀 바꾸지 않음), `classify_person_attributes_with_mask_and_wb_relaxed`는
`**kwargs`로 이미 전달 구조라 코드 변경 없이 받음. `scripts/
run_exp034_val_min_zero_sat_min_sweep.py`로 21 crop × 42 cell × 5 조명 = 210
cell 전수에 대해 `classify_person_attributes_with_mask_and_wb_relaxed`를 Mask+WB
포함 전체 경로로 직접 측정했다(EXP-033 섹션 5처럼 근사하지 않음). Baseline은
val_min=35/sat_min=25(production c_wb와 동일한 이분법)로 EXP-033의 c_wb 수치와
정확히 일치함을 재확인해 측정 파이프라인의 정합성을 검증했다. Regression Test:
`tests/test_attribute_color.py`에 4개 추가 - sat_min 파라미터가 실제로 전달되는지
(기본값 유지 시 결과 불변, 다른 값이면 결과가 바뀜을 증명하는 두 합성 픽셀 Case),
White Balance 변형에도 그대로 전달되는지, 그리고 위 4번에서 발견한 비단조
메커니즘을 결정론적 합성 픽셀(진짜 어두운 다수+중간 채도 소수 오염 혼합)로
고정하는 회귀 테스트(`test_sat_min_relaxation_is_not_monotonic_middle_value_
can_be_worse_than_both_extremes`). `pytest tests/ -q` 265 passed/7 skipped
(기존 261에서 신규 4개만 추가, 회귀 없음).

## 9. 재발 방지 대책
1. **Regression Test**: sat_min이 실제로 전달되는지(파라미터 배선)와, 비단조
   메커니즘(중간 지대에서만 걸리는 함정) 자체를 결정론적 합성 픽셀로
   `tests/test_attribute_color.py`에 고정했다 - 향후 누군가 이 필터 체인을
   다시 건드려도 "중간값이 양쪽 극단보다 나쁠 수 있다"는 사실이 테스트로 드러난다.
2. **방법론 원칙(재사용 가능)**: 한 Threshold 파라미터에서 확인한 단조 추세를
   유사한 역할의 다른 파라미터에 그대로 가정하지 않는다 - 이번에 val_min(단조)과
   sat_min(비단조)이 서로 다른 동역학을 보였다는 것 자체가 앞으로 이 프로젝트의
   다른 Threshold 튜닝(Loitering 초, BestShot Score 가중치 등)에도 적용할 경계심
   이다. 2차원 이상의 파라미터를 다룰 때는 Grid Search 전에 먼저 1차원씩 개별
   Sweep으로 단조성 여부를 확인하고, 비단조라면 중간값을 섣불리 보간하지 않는다.
3. **근사 재확인 원칙**: Hyperparameter 후보를 결정할 때 사후 분석(근사 함수)으로
   먼저 추세를 저렴하게 확인하는 것은 유효한 전략이지만, 실제 production 경로
   (이번에는 Mask+WB)에서 반드시 재확인한 뒤에야 Decision에 반영한다 - 이번에는
   근사가 맞았지만(val_min), 항상 그렇다고 가정해서는 안 된다는 것을 다음 세션
   에도 적용 가능한 절차로 남긴다.
4. **Config/실험 기록**: val_min=0/sat_min=20이라는 최종 후보값과 그 근거(둘 다
   n=21 Sweep 전수 측정, 사후 추정 아님)를 `src/attributes/color.py`의 docstring과
   `experiments/EXP-034/experiment.md`에 남겨, GT 라벨 재검증(Next Action 1번,
   이제 3회 이월)이 끝난 뒤 production 승격을 검토할 때 "왜 이 값인가"를 추측
   없이 확인할 수 있게 했다.
