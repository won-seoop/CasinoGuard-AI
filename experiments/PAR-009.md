# PAR-009 BestShot Position Score "경계 근접"과 "실제 잘림" 혼동 문제 개선 (FC-003)

관련 실험: EXP-004, EXP-018

## 1. 한줄 요약
BestShot Position Score가 bbox와 프레임 경계 사이 거리(margin 2%)만 보고 실제로
잘렸는지와 무관하게 페널티를 주던 문제를, bbox가 경계에 실제로 닿았는지(boundary_eps
2px) 판정하는 방식으로 바꿔, 합성 Ground Truth 기준 근접-비잘림 구간의 False Positive
Rate를 91.7%(11/12)에서 25.0%(3/12)로 줄였다.

## 2. 문제가 뭐였는가?
EXP-004에서 32개 Track의 BestShot 결과를 육안 검토하던 중, Track 1의 최종 선택
프레임이 Position Score 0.3점(페널티)을 받았는데도 실제로는 잘리지 않은 좋은 전신
사진이었다는 것을 발견했다(FC-003으로 등록). 원인은 `position_score()`가 bbox와
프레임 경계 사이 거리가 margin_ratio(기본 2%) 이내면 실제 잘림 여부와 무관하게 무조건
0.3점을 주는 이진 로직이었기 때문이다. 이번 PAR은 이 문제를 실제로 수정하고 정량
검증한 기록이다.

## 3. 왜 이 문제가 중요했는가?
BestShot은 카지노 CCTV Forensic 검색에서 "이 사람이 누구인지" 딜러/보안요원이 한눈에
파악하는 데 쓰는 대표 이미지다. Position Score가 "근접"과 "잘림"을 혼동하면, 실제로는
전신이 온전히 보이는 좋은 사진이 단지 경계 근처에 서 있었다는 이유만으로 낮은 점수를
받아 최종 대표 프레임 선택에서 밀려날 수 있다. 이는 개별 서브 점수 하나의 문제로
끝나지 않는다 — BestShot Score는 Confidence+Sharpness+Size+Occlusion+Position의 합산이므로,
다른 서브 점수가 낮은 Track(예: 흐릿하거나 작게 찍힌 경우)에서는 Position Score의 이
오차가 최종 대표 프레임 선택 자체를 뒤바꿀 수 있다. 카지노 게이밍 플로어처럼 사람이
많고 카메라 화각 경계 근처를 지나는 동선이 흔한 환경에서는 이 오차가 발생할 빈도 자체가
더 높다.

## 4. 원인이 뭐였는가?
`src/bestshot/scorer.py`의 기존 `position_score()` 코드를 직접 분석해 확인했다:
`margin_x, margin_y = frame_w*margin_ratio, frame_h*margin_ratio` 로 절대 거리 마진을
계산한 뒤, bbox의 어느 한 변이라도 이 마진 이내면(`x1<=margin_x or ...`) 실제 클리핑
여부와 무관하게 0.3점을 반환했다. EXP-004 Track 1 케이스에서는 다른 서브 점수
(Sharpness 0.968, Size 1.0, Occlusion 0.946)가 높아 우연히 상쇄됐을 뿐, 로직 자체는
부정확했다 — "경계와의 거리"라는 Proxy가 "실제로 화면 밖으로 나가 일부가 안 보임"이라는
진짜 현상과 다른 것을 측정하고 있었다.

## 5. A를 고민하였는데 왜 안 했는가?
**margin_ratio 값 자체를 더 작게 튜닝(예: 2%→0.2%)**. 코드 한 줄만 바꾸면 되는 가장
간단한 방법이었지만, 여전히 "거리 기반 근접" 이진 임계값이라는 같은 구조적 한계를
갖고 있어 채택하지 않았다. 어떤 값을 골라도 Ground Truth 없이는 근거가 없고
(EXP-018 실험을 설계하기 전까지는 애초에 "얼마나 틀렸는지"조차 측정할 방법이 없었다),
값을 줄일수록 근접-비잘림 구간의 False Positive는 줄어들지만 해상도별로 픽셀 스케일이
달라 일반화되지 않으며, 근본적으로 "근접"과 "잘림"을 여전히 혼동한다는 개념적 문제는
그대로 남는다.

## 6. B를 고민하였고 왜 적용했는가?
**bbox가 프레임 경계에 실제로 닿았는지(boundary_eps 기반) 판정하고, 닿은 변의 개수로
점수를 등급화**하는 방식을 채택했다. 실제 카메라 프레임은 사람의 "보이는 부분"만
담으므로, 몸이 진짜로 잘린 경우 Detector의 bbox 좌표 자체가 이미지 경계(0 또는
frame_w/frame_h)에 거의 정확히 맞닿는다는 것이 핵심 통찰이다. boundary_eps(기본 2px)는
Detector 좌표의 반올림 오차만 흡수할 정도로 작게 잡아 "근접"과 "실제로 닿음"을
구분했다. EXP-018에서 합성 Ground Truth로 직접 측정한 결과 근접-비잘림 구간 False
Positive Rate가 91.7%→25.0%로 줄었고, 실제로 잘린 프레임에 대한 Recall도 100%→99.3%로
거의 그대로 유지돼 A보다 근본적으로 더 정확하다는 것을 확인했다.

## 7. 어떤 방식으로 검증했는가?
Wikimedia 원본 영상은 이 원격 세션에서 접근 불가(egress 정책, EXP-010/014~017과 동일한
제약)해 ultralytics 내장 `bus.jpg`에서 YOLO11n으로 실제 검출한 사람 1명(conf=0.878,
192×504px 전신 crop)을 810×1080 배경 위 다양한 위치(수평 192프레임 + 수직 113프레임,
8px 간격)에 합성했다. 합성 좌표로부터 각 프레임의 "실제 잘림 여부"를 기하학적으로
정확히 계산해 Ground Truth로 삼고(육안 라벨링이 아님), 각 합성 프레임에 실제 YOLO11n
(conf=0.25, imgsz=640)을 다시 돌려 얻은 검출 bbox를 legacy/new `position_score`에
그대로 입력해(production과 동일 경로) Confusion Matrix를 계산했다. `tests/test_bestshot_scorer.py`
에 5개 Unit Test를 추가하고 기존 6개는 무수정으로 통과시켜 하위 호환을 확인했으며,
전체 `pytest tests/` 100 passed/7 skipped로 Regression Test를 완료했다.

## 8. 개선된 수치적인 결과가 무엇이었는가?

| Metric | Before (margin 2%) | After (boundary_eps 2px) |
|---|---|---|
| Accuracy (n=301) | 0.9635 | 0.9867 |
| Precision | 0.9317 | 0.9803 |
| Recall | 1.0 | 0.9933 |
| False Positive 개수 | 11 | 3 |
| **근접-비잘림 구간 False Positive Rate (n=12)** | **0.917 (11/12)** | **0.25 (3/12)** |
| 실제 잘림 구간 Recall (n=150) | 1.0 | 0.993 |

## 9. 재발 방지 대책
- `tests/test_bestshot_scorer.py`에 FC-003 재현 테스트(`test_position_score_legacy_flags_near_edge_as_clipped_new_does_not`)를
  포함한 5개 테스트를 고정해, 향후 `position_score()`를 다시 수정하더라도 "근접만으로
  페널티를 주는" 회귀가 생기면 즉시 실패하도록 했다.
  legacy 함수는 삭제하지 않고 `position_score_margin_legacy()`로 이름만 바꿔 남겨,
  향후 다른 Position Score 개선안이 나오면 같은 Ground Truth 실험(EXP-018)으로 다시
  비교할 수 있게 했다.
- EXP-018의 합성 Ground Truth 생성 스크립트(`scripts/run_exp018_bestshot_position_score_fix.py`)를
  재사용 가능한 형태로 남겨, boundary_eps 등 파라미터를 바꿀 때마다 동일한 방식으로
  재측정할 수 있게 했다.
- 남은 한계(3건의 잔여 False Positive, 1건의 False Negative)는 모두 Ground Truth 경계값
  (`gt_min_gap_px==0`) 또는 boundary_eps 문턱과 거의 정확히 맞물리는 극단적 케이스임을
  experiment.md Failure Cases에 정직하게 기록해, 향후 boundary_eps를 튜닝할 근거로
  남겼다.
