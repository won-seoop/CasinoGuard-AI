# PAR-019 Attribute 색상 분류 Segmentation Mask 영역 분리로 배경 Bleed 개선

관련 실험: EXP-025, EXP-026, EXP-027, EXP-028

## 1. 한줄 요약
Attribute 색상 분류(method b/b_wb)가 고정 비율 사각형으로 배경을 "근사적으로만" 제외하는
구조적 한계를 person Instance Segmentation Mask로 교체해(대안 C), White Balance와
독립적으로 작동함을 확인하고 둘을 결합(c_wb)해 n=21 Ground Truth 기준 Overall Accuracy를
26.2%(b) → 38.1%(c_wb)로, GT=black Accuracy를 39.1% → 55.5%로 개선했다.

## 2. 문제가 뭐였는가?
EXP-025~027에서 채택한 method b(대안 B)는 상/하의 영역을 세로 비율로 자르고 좌우
side_margin_ratio=0.12(12%)만큼 고정폭을 제외해 배경 Bleed를 줄이려 했다. 하지만 이 마진은
person의 실제 체형·자세와 무관한 고정값이라, 배경이 그보다 넓게 섞이는 경우(팔을 벌린
자세, 좁은 체형, Wide-angle Crop)에는 여전히 Hue 다수결이 배경 색으로 오염됐다. EXP-027이
coco128 n=21로 재검증한 결과 method b_wb(현재 최고 실험값)조차 Overall Accuracy 32.4%,
GT=black Accuracy 49.1%에 그쳐 production 전환 임계치에 한참 못 미쳤고, "더 근본적인 영역
분리 방법(Segmentation Mask)"을 다음 후보로 명시적으로 이월했다.

## 3. 왜 이 문제가 중요했는가?
카지노 CCTV는 사람이 밀집하고 복장 색상이 다양한 환경이라, "이 Track이 입은 옷 색"은 VMS
검색("빨간 옷을 입은 사람을 찾아줘")의 핵심 Metadata다. 이 분류가 배경·조명에 취약하면
같은 사람이 Frame마다 다른 색으로 기록되어 검색 결과가 신뢰를 잃는다. 연쇄 영향: Attribute
오분류 → Metadata 검색 정확도 저하 → VMS 검색 결과에 대한 운영자 신뢰 저하 → 결국
Attribute Metadata 자체를 VMS에 연결하지 못하는 상태가 장기화(EXP-025부터 EXP-027까지
3회 연속 "MetadataStore/VMS 연결 보류" 결정이 반복된 이유이기도 하다). 이 문제를 해결하지
못하면 Stretch Goal 중 하나(Attribute Metadata)가 "구현했지만 쓸 수 없는" 상태로 영구히
남는다.

## 4. 원인이 뭐였는가?
EXP-028에서 두 원인을 분리해 실측했다. (1) 영역 분리 자체의 부정확성: method b의 고정
비율 사각형은 person 실제 윤곽이 아니므로 배경 픽셀이 구조적으로 섞인다 - Segmentation
Mask(대안 C, WB 없음)로 교체하는 것만으로 Overall Accuracy가 26.2%→35.2%, GT=black
Accuracy가 39.1%→52.7%로 올랐다(코드/Config 변경은 "영역을 어떻게 고르는가"뿐). (2) 조명
Cast로 인한 Hue 왜곡: 대안 C 단독의 GT=black→blue 오분류율은 cool_cast에서 50.0%로 여전히
높았다(b_wb의 22.7%보다도 나쁨) - Mask는 이 원인을 전혀 해결하지 못한다는 것을 로그
(`results/EXP-028/summary.json`의 `gt_black_misclassified_as_blue_rate_by_condition`)로
직접 확인했다. 즉 두 원인(배경 Bleed, 채널 Cast)은 서로 다른 메커니즘이고, 기존 실험들은
이를 분리하지 않은 채 하나의 Accuracy 숫자로만 비교해 왔다.

## 5. A를 고민하였는데 왜 안 했는가?
대안 A는 "Segmentation Mask 없이, side_margin_ratio를 더 크게 키우는 것"(사각형 마진을
0.12에서 더 큰 값으로 조정)이었다. 장점은 추가 모델이 필요 없어 구현/추론 비용이 0이라는
점이다. 하지만 이 방식은 EXP-028 Problem에서 분석한 구조적 한계를 그대로 가진다 - 마진을
고정값으로 더 키우면 체형이 넓은 사람의 옷 영역 자체를 잘라내는 반대 방향 오류가 생기고,
여전히 person의 실제 자세/체형에 적응하지 못한다. 근본 원인(사각형이 윤곽이 아니다)을
건드리지 않고 임계값만 조정하는 방식이라 폐기했다(EXP-025/026에서 이미 "고정 비율/임계값
튜닝"의 한계를 반복적으로 확인한 것과 같은 결론).

## 6. B를 고민하였고 왜 적용했는가?
대안 B(채택)는 person Instance Segmentation(yolo11n-seg.pt)으로 실제 윤곽 Mask를 얻어
배경을 픽셀 단위로 제외하는 방식이다. Detector(yolo11n.pt)와 별도 모델을 하나 더 돌려야
한다는 비용(실측: 추론 시간 1.29배, 모델 용량 +0.57MB)이 있지만, person의 실제 형태에
적응하므로 체형/자세에 무관하게 배경을 정확히 제외한다 - EXP-028 실측에서 A(마진 조정)
없이도 바로 Accuracy 개선(35.2%, 52.7%)을 보여 그 가설이 맞았음을 확인했다. 추가로
White Balance(EXP-026)와 독립적으로 작동함을 확인해 둘을 결합(c_wb)하면 각 기법의 이득이
합산된다는 것도 실측으로 보여, 단일 기법보다 결합이 더 유리하다고 판단했다.

## 7. 어떤 방식으로 검증했는가?
- **Dataset**: EXP-027과 완전히 동일한 coco128(실제 COCO 128장) 기반 person crop n=21,
  수동 Ground Truth(지침 31). 재현성은 동일 Detector(yolo11n.pt, conf=0.4)로 crop 이름이
  21개 모두 그대로 재현되는지 확인하는 방식으로 검증했다.
- **환경/Configuration**: `.venv`(Python 3.11) + ultralytics 8.4.173, CPU 전용.
  `src/attributes/color.py`에 기존 method b/b_wb Config(head_skip_ratio=0.22,
  upper_end_ratio=0.55, foot_skip_ratio=0.08)는 변경하지 않고 대안 C/C+WB를 별도 함수로
  추가(`classify_person_attributes_with_mask`,
  `classify_person_attributes_with_mask_and_wb`).
- **Metric**: Overall Accuracy(n=21 x 5 조명 x 상/하 = 210셀), Normal 조명만, GT=black
  Accuracy, GT=black→blue 오분류율(strong_light/cool_cast로 조건 분리), Segmentation Mask
  매칭률(IoU>=0.5), 추론 Overhead(ms/image), 모델 크기(MB).
- **Baseline/비교 방식**: EXP-027이 측정한 baseline/a/b/b_wb 네 가지 수치를 그대로 재실행해
  동일함을 재확인하고, 그 위에 c/c_wb를 동일 Harness(`scripts/run_exp028_attribute_
  segmentation_mask.py`)로 추가 측정 - "전체 평균"과 "FC-012가 겨냥한 GT=black→blue 셀"을
  항상 분리해서 보는 것은 EXP-026/027에서 확립한 분석 패턴을 그대로 따랐다.
- **Regression Test**: `tests/test_attribute_color.py`에 신규 함수(`split_upper_lower_
  by_mask`, `classify_person_attributes_with_mask`, `classify_person_attributes_with_
  mask_and_wb`, `region_dominant_color_from_pixels`) Unit Test 9개를 추가(배경 Bleed가
  method b를 속이지만 Mask는 속지 않는 경우, Mask 매칭 실패 시 Fallback 경로 포함). 전체
  스위트 197 passed/7 skipped(기존 185 passed에서 증가, 회귀 없음).

## 8. 개선된 수치적인 결과가 무엇이었는가?

| Metric | Before (b, production) | After (c_wb) |
|---|---|---|
| Overall Accuracy (n=21) | 26.2% (55/210) | 38.1% (80/210) |
| Normal 조명만 | 33.3% | 38.1% |
| GT=black Accuracy | 39.1% (43/110) | 55.5% (61/110) |
| GT=black→blue (strong_light) | 18.2% | 27.3% (소폭 악화) |
| GT=black→blue (cool_cast) | 59.1% | 22.7% |

| Metric | Before (b_wb, 기존 최고) | After (c_wb) |
|---|---|---|
| Overall Accuracy | 32.4% | 38.1% |
| GT=black Accuracy | 49.1% | 55.5% |
| 추론 비용 | Detector만(71.2ms/img) | Detector+Segmenter(91.6ms/img, 1.29x) |

## 9. 재발 방지 대책
- **Regression Test**: `tests/test_attribute_color.py`에 대안 C/C+WB Unit Test 9개 추가
  (배경 Bleed 극복, Mask 매칭 실패 Fallback, Empty Crop 처리). 전체 197 passed/7 skipped.
- **Config/코드 분리 유지**: 대안 C/C+WB는 `method="c"/"c_wb"`라는 별도 이름으로만 노출되고
  production 기본값(`method="b"`)의 동작은 전혀 바뀌지 않는다(`test_method_b_unaffected_
  by_white_balance_addition`과 동일 원칙) - 실험적 방법이 뜻하지 않게 기본값을 바꾸는 사고를
  막는다.
- **Metric 슬라이싱 습관 유지**: "전체 평균이 올랐다"만 보고 FC-012가 해결됐다고 결론
  내리지 않도록, GT=black→blue 오분류율을 조명 조건별로 항상 분리해서 보는 패턴
  (`gt_black_misclassified_as_blue_rate_by_condition`)을 EXP-028에도 그대로 적용했고,
  그 결과 "대안 C는 Cast 문제를 해결하지 못한다"는 반직관적 사실을 숨기지 않고 기록했다.
- **Edge 비용 문서화**: Segmenter 추가 Overhead(1.29x, +0.57MB)를 experiment.md에 명시해
  향후 실시간 파이프라인에 연결할 때(Next Action) 이 비용을 다시 측정해야 한다는 것을
  코드가 아닌 문서에도 남겼다.
- **Production 승격 임계치 재확인 없이 연결하지 않음**: c_wb가 수치상 최고를 기록했어도
  MetadataStore/VMS 연결은 보류를 유지해, "측정된 개선"과 "배포 가능한 품질"을 혼동하지
  않도록 했다(EXP-025~027과 동일 원칙의 반복 적용).
