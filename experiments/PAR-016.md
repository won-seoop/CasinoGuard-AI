# PAR-016 Attribute 색상 분류에서 검정 옷이 필터-폴백 버그로 피부색으로 오분류되는 문제 수정

관련 실험: EXP-025(Attribute Metadata 상의/하의 색상 분류 Baseline/대안 A/대안 B)

## 1. 한줄 요약
그림자/하이라이트 픽셀을 제거하는 필터가 진짜 검정 옷(저채도·저명도)까지 항상 제외시켜
클로즈업 crop에서 소수 피부색 픽셀만 남아 Hue 다수결을 오염시키던 버그를(대안 B 최초 구현이
Baseline보다도 낮은 정확도를 내는 역설로 실측 발견) 필터 통과 비율 기반 폴백과 피부색 제외
필터로 수정해, 동일 조건 Accuracy를 32%→40%(Baseline 대비), 조명 변형 평균 안정성을
15%→40%(대안 B 자체 1차 대비)로 개선했다.

## 2. 문제가 뭐였는가?
지침 19 Attribute Metadata(상의/하의 색상)를 구현하면서, 그림자·하이라이트 픽셀을 걸러내고
남은 픽셀의 Hue 다수결로 색을 정하는 `region_dominant_color()`(대안 B)를 만들었다. 실제
YOLO11n 검출 crop 5개(ultralytics 번들 `zidane.jpg`/`bus.jpg`)로 측정했더니, 대안 B의
전체 평균 Accuracy가 16%로, 상/하의조차 구분 못 하는 Baseline(32%)보다도 낮게 나왔다 —
"더 정교한 필터링을 추가했는데 오히려 더 나빠지는" 역설적 결과였다.

## 3. 왜 이 문제가 중요했는가?
VMS Search(지침 17)가 "빨간 상의를 입은 사람"처럼 Attribute 기반 검색을 지원하려면 색상
분류가 최소한의 신뢰도를 가져야 한다. 카지노 환경은 특히 검정/네이비 정장 차림의 비중이 높고
(이번 평가 Dataset 5개 중 4개도 우연이 아니라 실제로 정장/코트 차림이 많았다), 조명이 강하거나
자주 바뀌는 카지노 플로어에서 검정 옷이 엉뚱한 색(피부색 계열)으로 분류되면, 색상 기반 검색이
가장 흔한 케이스(검정 옷)에서부터 신뢰할 수 없게 된다. 더 나아가 "필터를 추가하면 무조건
좋아질 것"이라는 안이한 가정이 실제로는 더 나쁜 결과를 낳을 수 있다는 것을 실측으로 확인한
사례로, 향후 Attribute 확장(가방/모자 여부 등) 설계에도 같은 함정(다수 Majority 픽셀이
필터에 걸려 사라지고 소수 Noise가 남는 경우)을 주의해야 한다는 교훈을 남긴다.

## 4. 원인이 뭐였는가?
`results/EXP-025/predictions.csv`의 `normal` 조명 조건 행을 직접 조사했다: `zidane_0`/
`zidane_1`(얼굴+상반신 클로즈업 crop, 전신이 아님)의 상의 GT는 `black`인데 대안 B 예측은
각각 `red`/`green`이었다. 원인을 코드로 추적한 결과 두 가지가 겹쳐 있었다:
1. `head_skip_ratio=0.22`만으로는 클로즈업 crop의 턱선·목·뻗은 손 피부 픽셀을 다 제거하지
   못했다(가설이었던 "고정 비율 분할이 Framing 차이에 취약하다"가 실제로 확인됨).
2. (진짜 코드 버그) `region_dominant_color()`의 S/V 필터(`sat_min=25`)는 저채도 픽셀을
   전부 제외하는데, 진짜 검정 옷은 채도도 0에 가까워 이 필터에 의해 **거의 항상 통째로
   제외**됐다. 최초 구현은 "필터링 후 남은 픽셀이 0개일 때만" 전체 픽셀로 fallback했는데,
   소수 피부색 픽셀이 필터를 통과해 남아있으면 그 개수가 0이 아니므로 fallback이 발동하지
   않고 소수 피부색이 그대로 최종 결과가 됐다.

## 5. A를 고민하였는데 왜 안 했는가?
**대안 A: 고정 비율 상/하 영역 분할만 적용하고 그림자/하이라이트/피부색 필터링은 하지 않는다
(단순 영역별 평균 BGR).** 구현이 더 단순하고 Baseline보다 상/하 구분이 가능하다는 장점이
있었다. 하지만 실측 결과(전체 Accuracy 28%, 조명 안정성 30%)가 Baseline(32%/35%)보다도
낮았다 — 배경 Bleed와 밝기 변화에 그대로 노출되기 때문이다(가설 2번이 그대로 확인됨). 필터링
없이는 애초에 이 Attribute 분류가 실전에서 쓸 수 있는 수준에 도달하기 어렵다고 판단해 더
깊이 투자하지 않았다.

## 6. B를 고민하였고 왜 적용했는가?
**대안 B(채택, 버그 수정 포함): 영역 분할 + 그림자/하이라이트/피부색 픽셀 제거 + Hue
다수결, 단 필터링된 픽셀 비율이 낮으면(`min_filtered_fraction=0.3` 미만) 필터를 신뢰하지
않고 원본 전체 픽셀로 되돌아간다.** 최초 구현(개수가 0일 때만 fallback)이 역설적으로 더
나쁜 이유를 원인 분석으로 명확히 특정했기 때문에, "필터 통과 비율이 낮다는 것 자체가 필터링된
집합이 다수를 대표하지 못한다는 신호"라는 일반화된 규칙으로 수정했다. 추가로 피부색 HSV
휴리스틱(`_is_skin_like`)을 명시적으로 추가해 클로즈업 crop의 얼굴/손 오염을 직접 겨냥했다.
수정 후 재측정에서 대안 B가 Baseline과 대안 A를 모두 앞섰다(아래 8번).

## 7. 어떤 방식으로 검증했는가?
- Dataset: ultralytics 번들 실제 사진(`zidane.jpg`, `bus.jpg`) + YOLO11n(conf=0.3)
  Person Detection으로 얻은 crop 5개(1개는 Occlusion으로 평가 제외). Ground Truth는 Read
  도구로 각 crop을 직접 눈으로 확인해 수동 라벨링(`scripts/run_exp025_attribute_color.py`의
  `GROUND_TRUTH`).
- Environment: 원격 자동화 세션, Python 3.11.15, opencv-python-headless/numpy/ultralytics
  신규 venv, CPU 전용.
- Configuration: `src/attributes/color.py`의 Baseline/대안 A/대안 B 세 구현을 동일 crop,
  동일 조명 조건 세트(정상/저조도/강한조명·역광/난색 Cast/한색 Cast)에 대해 전부 실행.
- Metric: Attribute 분류 Accuracy(예측 색상 버킷 == GT 버킷), 전체 평균, 조명 변형 4종
  평균("안정성").
- Baseline: `whole_bbox_mean_color()`(상/하 구분 없음, 관대하게 "상의 또는 하의 GT 중
  하나라도 맞으면 정답"으로 채점).
- 비교 방식: 수정 전/후 **동일** Dataset·동일 조명 조건·동일 pytest로 재측정(Before/After
  표, 지침 37).
- Regression Test: `tests/test_attribute_color.py` 신규 26개(수정 전 버그를 재현하는
  `test_skin_tone_minority_does_not_flip_black_garment` 포함) + 전체 프로젝트 pytest
  179 passed / 7 skipped(기존 skip 유지, 회귀 없음).

## 8. 개선된 수치적인 결과가 무엇이었는가?

| Metric (대안 B) | Before (필터 버그 있음) | After (필터-폴백 수정) |
|---|---|---|
| 전체 평균 Accuracy | 16% | 40% |
| 조명 변형 평균 Accuracy(안정성) | 15% | 40% |
| normal 조명 Accuracy | 20% | 40% |
| Baseline 대비 순위 | Baseline(32%)보다 낮음 | Baseline(32%)보다 높음 |
| 대안 A 대비 순위 | 대안 A(28%)보다 낮음 | 대안 A(28%)보다 높음 |

(원본 수치: `results/EXP-025/summary.json`, 행 단위 원시 데이터: `results/EXP-025/predictions.csv`)

새로운 Trade-off: 대안 B는 Baseline/대안 A보다 나아졌지만 절대 Accuracy는 여전히 40%로
낮다. n=5의 작은 평가 Dataset과 낮은 색상 다양성(검정 편중) 때문에 이 결론을 더 큰
Dataset에 일반화할 수는 없다(EXP-025 Analysis에 명시). 또한 FC-012(조명 색 Cast로 인한
검정→파랑 오분류)는 이번 수정으로 해결되지 않고 백로그로 남았다.

## 9. 재발 방지 대책
- `tests/test_attribute_color.py`에 이번 버그를 직접 재현하는 Regression Test
  (`test_skin_tone_minority_does_not_flip_black_garment`, `test_exclude_skin_false_disables_skin_filter`)
  를 추가해, 향후 `region_dominant_color()`의 필터 조건을 바꿀 때 동일한 "다수 픽셀이
  필터에 전부 걸려 사라지는" 회귀가 재발하면 즉시 실패하도록 고정했다.
- `min_filtered_fraction` 같은 "필터 신뢰 가능 여부" 임계값을 코드 주석에 왜 필요한지
  (어떤 실제 버그를 막기 위한 것인지) 명시해, 다음에 유사한 필터를 추가하는 사람이 같은
  함정("개수가 0일 때만 fallback"은 불충분하다)에 빠지지 않도록 기록했다.
- Attribute 색상 분류를 MetadataStore/VMS API에 바로 연결하지 않고 독립 모듈
  (`src/attributes/`)로 유지해, 검증되지 않은 Accuracy(40%)가 운영 Metadata 품질에
  영향을 주지 않도록 분리했다(EXP-025 Decision).
- FC-012(조명 색 Cast로 인한 검정→파랑 오분류)를 Failure Case로 명시 등록해 다음 세션이
  이 한계를 인지한 상태로 작업을 이어가도록 했다.
