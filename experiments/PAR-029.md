# PAR-029 Person Re-ID Gamma-Background+White Balance 결합: Cast 문제는 해결, Occlusion 새 Trade-off 발견

관련 실험: EXP-037 (FC-013 배경 기반 Gamma 보정), EXP-038 (Gamma+White Balance 결합)

## 1. 한줄 요약
Re-ID 임베딩의 조명 Cast(warm_cast/cool_cast) 붕괴 문제를, 이미 Attribute 분류에서
검증된 White Balance를 배경 기반 Gamma 보정 뒤에 결합해 Top-1을 최대 82.2pp까지
개선했지만, 그 과정에서 세 방법 모두에서 일관된 Occlusion 성능 저하(FC-014)를 코드
레벨로 원인까지 규명하며 새로 발견해 production 적용은 보류했다.

## 2. 문제가 뭐였는가?
EXP-037(배경 기반 Gamma 보정)이 FC-013의 전역 노출 붕괴(low_light/strong_light)는
크게 완화했지만, 채널 Cast(warm_cast/cool_cast)는 거의 그대로였고 오히려 YOLO
Backbone 임베딩 기준 2.2~8.9pp 소폭 악화된 채로 남아 있었다. Gamma는 전역 밝기만
보정하므로 채널 간 상대적 편향(Cast)을 겨냥하지 못하는 것이 당연한 결과였다.

## 3. 왜 이 문제가 중요했는가?
카지노는 강한 인공조명과 난색/한색 조명이 혼재하는 대표적인 환경이다(CLAUDE.md
지침 4 - 카지노처럼 사람이 많고 조명이 복잡한 환경). Person Re-ID는 여러 카메라에
걸쳐 같은 사람을 재식별해야 하는데, 조명 Cast가 카메라마다 다르면 Re-ID 임베딩이
"같은 사람인데 다른 사람처럼" 보이게 만들 수 있다. 이 Cast 민감성이 그대로 남아
있으면 다중 카메라 Re-ID(지침 18, 아직 Core MVP 이후 Stretch 범위)로 확장할 때
근본적인 장애물이 된다 - Attribute Metadata(FC-012)에서 이미 같은 유형의 문제를
겪었고 White Balance가 부분적으로 효과가 있었던 선례가 있어, 같은 해법이 Re-ID에도
통하는지 반드시 검증이 필요했다.

## 4. 원인이 뭐였는가?
EXP-037/038 실측 데이터와 코드 분석에 근거한다(추측 아님):
- Cast 문제의 원인: `adaptive_gamma_correct_from_background()`는 배경의 "평균 밝기"
  하나만으로 감마를 추정하고 전체 채널에 동일한 지수를 적용한다 - 채널 간 상대적
  비율(Cast)은 구조적으로 보존된다. White Balance(`white_balance_gray_world()`)는
  반대로 채널별 독립 게인을 계산하므로 이 Cast를 직접 겨냥한다(EXP-026에서 이미 같은
  메커니즘으로 Attribute Cast 문제에 부분 효과가 검증됨).
- Occlusion 저하의 원인: 직접 코드 레벨로 재현해 확인했다. 같은 crop(`000000000368_0`)
  에 Occlusion(중립 회색 `(120,120,120)` 패치, bbox의 약 20~30% 면적)을 적용하기
  전/후로 White Balance 게인을 계산하면 B/G/R 게인이 `[1.32, 0.92, 0.87]`에서
  `[1.22, 0.91, 0.93]`로 뚜렷이 이동한다 - 중립 회색 패치 자체가 Gray World 가정이
  요구하는 "완벽한 무채색"이라, crop의 상당 면적을 차지하면 채널 평균을 인위적으로
  중립 쪽으로 끌어당겨 같은 사람의 가려진/가려지지 않은 뷰가 서로 다른 보정을 받게
  만든다.

## 5. A를 고민하였는데 왜 안 했는가?
**대안 A: Gamma-Background 단독 유지(EXP-037 상태로 동결, 추가 보정 없음).**
장점: 이미 검증되어 production 후보로 거론되던 상태를 유지하므로 추가 개발/검증
비용이 없고, EXP-037이 발견한 Occlusion 문제가 없다(이번 실험으로 신규 발견된
FC-014는 WB를 추가했을 때만 나타남).
선택하지 않은 이유: FC-013(b)(warm_cast/cool_cast)가 전혀 해결되지 않은 채로
남는다. 특히 Baseline(Color Histogram) 방법은 이 상태에서 Cast Top-1이 6.7~11.1%
(사실상 무작위 수준)에 머물러 있어, 카지노의 복잡한 조명 환경을 전혀 견디지 못하는
상태를 그대로 방치하는 셈이었다. "이미 검증된 것을 더 건드리지 않는다"는 안전함보다
"남은 절반의 문제(FC-013b)를 실제로 검증해보는 것"이 Roadmap이 명시한 최우선
Action이었다.

## 6. B를 고민하였고 왜 적용했는가?
**대안 B(채택): Gamma-Background 뒤에 White Balance를 추가 결합
(`gamma_background_then_white_balance`, EXP-030의 `b_wb_gamma`와 동일한 순서).**
세 가지 헤드라인 Overall Top-1 지표(Baseline/Candidate/Fusion) 전부에서 Gamma
단독보다 역전 없이 개선됐고(+17.5pp/+0.6pp/+14.3pp), 목표였던 warm_cast/cool_cast는
Baseline 기준 최대 +82.2pp까지 개선돼 사실상 해결 수준(88.9~100%)에 도달했다 -
이는 EXP-037이 production 채택 기준으로 쓴 것과 동일한 "헤드라인 집계 지표 전부
지배" 조건을 만족한다. A보다 이 조건에 더 적합했던 이유는, A는 검증된 범위를 넓히지
못하는 반면 B는 실측으로 그 범위를 실제로 넓혔기 때문이다 - 다만 그 대가(FC-014)를
숨기지 않고 함께 기록했다(아래 9번 참고).

## 7. 어떤 방식으로 검증했는가?
- Dataset: coco128 실제 person crop 45명(`results/EXP-027/crops`, EXP-027/036/037과
  완전히 동일 집합 - 실행 시 재탐지로 일치 재확인).
- Test Video/Query: EXP-036/037과 동일한 Query Protocol(RNG seed 42, 동일 호출
  순서) - 조명 4종(low_light/strong_light/warm_cast/cool_cast) + 기하 변형 3종
  (occlusion/bbox_jitter/flip), 45명 x 7 variant = 315 Query.
- 환경: Python 3.11, ultralytics 8.4.178, torch 2.14.1, opencv-python-headless
  5.0.0.93 (이번 세션 신규 설치).
- Configuration: `scripts/run_exp038_reid_wb_gamma_background.py` - EXP-037과
  동일한 배경 추출 로직을 재사용하되, 보정 함수를 Gamma-Background 단독(재현)과
  Gamma+WB(신규) 두 Pipeline으로 나란히 실행.
- Metric: Top-1, Top-5, mAP (Overall + Variant별 슬라이싱, `src/reid/matching.py`).
- Baseline: EXP-037 대안 B(Gamma-Background 단독)를 이 실험에서 그대로 재실행해
  재현성 확인(Overall Top-1이 EXP-037 기록값과 완전히 일치).
- 비교 방식: 동일 Gallery/Query/임베더(Color Histogram, YOLO11n-cls Backbone,
  50:50 Fusion) 조합에 보정 함수만 교체해 A/B 비교, Variant별 슬라이싱으로 "평균
  개선"에 숨겨진 회귀를 직접 확인.
- Regression Test: `pytest tests/ -q` 전체 재실행, 신규 함수
  (`gamma_background_then_white_balance`) Unit Test 3개 추가 - 수동 합성과 동일한
  결과인지, 과다노출 배경에 대한 어둡게 보정 방향이 WB를 거친 뒤에도 뒤집히지
  않는지, Cast가 있는 배경에서 WB 단계가 채널 편향을 실제로 완화하는지 검증.

## 9. 재발 방지 대책
- FC-014(Gamma-Background+WB 결합의 Occlusion 저하)를 신규 등록하고, Segmentation
  Mask로 White Balance 평균 계산을 person 픽셀에만 한정하는 방안을 다음 세션 후보로
  구체적으로 지정했다(experiments/EXP-038/experiment.md Next Action 1번) - 발견한
  문제를 "알고만 있는" 상태로 남기지 않고 다음 실험으로 연결한다.
- `gamma_background_then_white_balance()`에 EXP-038 검증 전까지 production
  연결 금지를 docstring에 명시해, 향후 세션이 "검증된 함수가 src/에 있으니 바로
  연결해도 된다"고 오해하지 않도록 했다(EXP-031/EXP-030의 미승격 함수들과 동일한
  관례 유지).
- Unit Test 3개(`TestGammaBackgroundThenWhiteBalance`)로 함수의 합성 순서(Gamma
  먼저, WB 나중)와 어둡게 보정 방향을 고정했다 - 테스트 작성 과정에서 직접 한 가지
  방향 가정 오류(과다노출 배경이 crop을 "밝게"가 아니라 "어둡게" 보정한다는 기존
  함수의 실제 동작을 반대로 가정)를 발견해 테스트를 수정했다. 이는 신규 보정 함수를
  추가할 때 방향성 가정을 직접 코드로 재검증하지 않으면 테스트 자체가 틀릴 수
  있다는 재발 방지 교훈이다.
- Variant별 슬라이싱(전체 7종)을 EXP-038에도 EXP-036/037과 동일하게 적용해 "평균만
  보고 결론 내리지 않는다"는 이 프로젝트의 핵심 원칙(PAR-018/023/026이 이미 같은
  패턴으로 실수를 방지한 전례)을 다시 한번 지켰다.
